résolu, clés top-level uniquement) → 39 sites candidats filtrés à 2 vrais bugs + 0 faux positif.

## Leçons

1. Le scan fillable multi-modèles (hors Employee/User/SuperAdmin) est une mine : les audits
   précédents se concentraient sur les 3 modèles du durcissement #3677 ; des modèles comme
   `Partner`, `OnboardingStep` avaient des appels cassés depuis plus longtemps.
2. `firstOrCreate(attrs, values)` : les clés sensibles vivent dans le 2ᵉ tableau — scanner
   uniquement le 1ᵉr tableau rate ces sites.
3. La famine CI (#3545) rend chaque push coûteux : annuler les runs obsolètes (commits
   superseded) avant de pousser est indispensable pour faire avancer la file.
4. Concurrence : les autres agents rafraîchissent les mêmes branches — vérifier
   `mergeable_state` avant chaque action, ne jamais force-push, consolider les doublons de PR.
