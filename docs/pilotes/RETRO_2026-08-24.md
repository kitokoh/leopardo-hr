## 3. Ce qui a marché (J1 → J6, 19-24/08)

- **Vélocité d'exécution très élevée** : **132 PRs mergées depuis le 19/08** (~22/j), avec une
  discipline de process remarquable (spec-first `.specify`, CHANGELOG en tête, `Closes #N`,
  protocole anti-doublon #2400, gates CI par module).
- **Paie multi-pays livrée** : packs DZ (golden 40+ cas, PDF, virements CNEP/EDX, recette pilote),
  FR (barème IR 2026 + SMIC), TN, CI, CM, SN, TR, EN (GB/US/CA) — **coverage Payroll 88,1 %** ✅.
- **Pointage consolidé** (ADR-0016) : fusion progressive Attendance/SmartAttendance en 5 phases,
  routes unifiées `/attendance/*`, géofence à chemin unique, corrections de pointage + workflow
  d'approbation (phases 1-3 mergées).
- **HR cycle de vie** : onboarding candidat→employé tracé, contrats ↔ statut, offboarding, checklist
  documents, timeline carrière, préavis légal par pays.
- **Comptabilité (module greenfield)** : socle data, CRUD contacts, paramétrage TVA/devises/séries,
  workflow documents + numérotation concurrent-safe, PDF ×4 langues, email/portail, journal,
  paiements, TVA multi-pays, audit RGPD, perf (benchmark 10k docs) — en cours de merge continu.
- **Qualité/process** : gates de coverage par module (≥ 70 %), OpenAPI + SDK régénérés à chaque PR,
  audits i18n et sécurité, runbooks détaillés, snapshots KPI datés reproductibles (#5158).

## 4. Ce qui n'a pas marché

- **CI saturée** : sur les 100 derniers runs, **49 en file/attente** (congestion des runners),
  16 cancelled (concurrence), 1 failure → 34 % de vert (66,7 % si on exclut les runs non démarrés).
  Leçon déjà documentée (#3545 « famine du pipeline ») non résorbée ; les merges en rafale
  aggravent l'effet.
- **Collisions de migrations répétées** (incident #1962) : préfixes dupliqués
  (`2026_08_23_000005`, `2026_08_24_000001`) constatés et corrigés 2× ce jour — signe que le
  protocole de nommage des migrations est contourné sous pression parallèle.
- **`main` a été livré cassé au moins 2×** : `dev-hub/sdk/MANIFEST.json` avec **marqueurs de conflit
  git commités** (hérités d'un merge raté, PR #5354) — la CI OpenAPI est restée rouge jusqu'à
  réparation ; la correction est livrée dans la PR #5387 (en revue).
- **Backlog d'issues en hausse** : 35 issues ouvertes (hors dependabot), en hausse vs 21 au 20/08 —
  les agents créent plus de tickets que le flux n'en ferme.
- **Ratio fix/feat 5,24** : 5,24 commits de correction pour 1 feature (cible 2,5) — une part
  importante de l'énergie part en re-travail (CI, collisions, style, rebases), pas en produit.
- **Funnel de prod fragilisé** (rapport QA 17/08) : création d'employé 500 sur main (corrigé),
  trial guidé bloqué en pending (worker de queue mort), OAuth Google inopérant pour les nouveaux
  comptes (#5171) — **décision produit toujours requise**.
- **Pilotes non engagés** : 6 jours après le lancement du plan, aucune signature — le risque gate
  est déjà actif.

## 6. Recommandation A/B/C — argumentée (pour le bilan J60, 17/10)

La recommandation est **conditionnelle aux mesures J46** (03/10). Aujourd'hui, les données
disponibles dessinent un scénario « B → C si rien ne bouge ».

- **A — Lever (poursuivre l'expansion)** : requis à J60 —
  CI ~100 % sur les 10 derniers jours ouvrés, coverage Payroll ≥ 80 % ✅ maintenu, **2 pilotes
  actifs/semaine prouvés** (KPI 5), MRR > 0, backlog issues ≤ 10, ratio fix/feat ≤ 2,5.
  Verdict probable à date : **non** (pilotes non signés, CI 34 %, issues 35, ratio 5,24).
- **B — Conditionnel (poursuivre avec conditions)** : le plus probable aujourd'hui —
  1) signer + onboarder **2 pilotes DZ avant J46** (débloquer les prérequis prod : workers de queue,
     OAuth Google — décision #5171) ; 2) stabiliser la CI (anti-famine #3545, gating des merges) ;
  3) fermer/rationaliser le backlog (35 issues → ≤ 10, doublons inclus) ; 4) plafonner le
  fix/feat (refactor hors-bug refusé, règle #5147 déjà en place).
- **C — Pause (consolider)** : déclencheurs — à J46 aucun pilote signé **et** MRR = 0 **et** CI
  toujours < 100 % → geler l'expansion (pas de pays n°2, pas de nouvelle feature hors DZ),
  consolider CI/backlog/qualité, re-lancer le programme pilote avec un dispositif allégé.
