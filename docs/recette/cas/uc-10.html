UC-10

Kiosque en mode dégradé / synchronisation Edge

Résilience ✔ exécuté Profil : Superviseur / Kiosque Module : Kiosque & EdgeSync

Description / préconditions

Vérifier le comportement de la borne lorsque le réseau vers le cloud est indisponible (pont on-prem edge/).

Prérequis : Kiosque local, coupure réseau simulée (mode hors-ligne ou API injoignable).

Résultat attendu

Le kiosque reste utilisable hors-ligne, met l'événement en file, affiche un état explicite, puis synchronise sans créer de doublon.

Étapes de test

  1. Charger le kiosque avec l'API accessible, puis couper l'accès réseau.
  2. Effectuer un pointage par matricule.
  3. Observer le message affiché et la mise en file locale.
  4. Rétablir le réseau et vérifier la reprise/synchronisation.
  5. Contrôler l'absence de doublon après resynchronisation.

Fiche de résultats

Note IA (/5) Observation IA Note humaine (/5) Observation humaine
4/5 Le pont local met chaque pointage en file SQLite (sync_status=queued) et incrémente queue_count (2 → 3 après un pointage) ; dead_letter_count=0. L'état est exposé par GET /local/status (online, queue_count, last_error, last_sync_at). La borne reste pleinement utilisable sans cloud. La resynchronisation vers le cloud n'a pas pu être validée de bout en bout : le point de synchronisation cloud n'est pas configuré en local (last_error=HTTP_404). — Non renseignée — éditable ci-dessous.

Votre évaluation humaine

Les notes saisies ici sont enregistrées dans le dépôt (docs/recette/notes-humaines.json) via l'API GitHub : elles sont donc versionnées et visibles par tous. Un jeton personnel GitHub est requis ; il reste stocké uniquement dans votre navigateur.

Configurer mon jeton GitHub

Créez un token sur github.com/settings/tokens avec le scope repo (token classique) ou la permission Contents: Read and write (token fin). Il n'est envoyé qu'à api.github.com et n'est jamais écrit dans le dépôt.
