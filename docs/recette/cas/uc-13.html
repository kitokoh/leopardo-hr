UC-13

Observabilité et santé de la plateforme

API ✔ exécuté Profil : Opérations (Ops) · Super Admin plateforme Module : Plateforme & observabilité

Description / préconditions

Vérifier les sondes de santé et la documentation API exposées.

Prérequis : Accès réseau à l'API de production.

Résultat attendu

/health renvoie 200 avec le détail des dépendances ; /health/live renvoie 200 ; /health/ready reflète fidèlement l'état réel (503 si dégradé) ; la documentation API est accessible.

Étapes de test

  1. Appeler GET /api/v1/health et relever statut, version et état des dépendances.
  2. Appeler GET /api/v1/health/live et GET /api/v1/health/ready.
  3. Ouvrir la documentation API (/docs).
  4. Comparer les informations de version avec le commit attendu.

Fiche de résultats

Note IA (/5) Observation IA Note humaine (/5) Observation humaine
4/5 Environnement local : GET /health → 200 (status:"ok") ; /health/live → 200 ; /health/ready → 200 avec matrice checks (database ok, redis ok/skipped, queue ok/sync, mail ok/array, failed_checks:[]). GET /demo-users → 404 (mode démo désactivé par défaut, conforme au durcissement documenté). La documentation /docs (Scramble) et la comparaison de version avec le commit attendu n'ont pas été vérifiées localement. — Non renseignée — éditable ci-dessous.

Votre évaluation humaine

Les notes saisies ici sont enregistrées dans le dépôt (docs/recette/notes-humaines.json) via l'API GitHub : elles sont donc versionnées et visibles par tous. Un jeton personnel GitHub est requis ; il reste stocké uniquement dans votre navigateur.

Configurer mon jeton GitHub

Créez un token sur github.com/settings/tokens avec le scope repo (token classique) ou la permission Contents: Read and write (token fin). Il n'est envoyé qu'à api.github.com et n'est jamais écrit dans le dépôt.
