# Leopardo RH — Dossier de référencement

Ce dossier contient les textes et champs prêts à être adaptés dans les plateformes de découverte. Il ne constitue pas une autorisation de publication : les comptes, URL canoniques, visuels finaux et éventuels paiements doivent être validés par l’équipe.

## Livrables

| Fichier | Usage |
|---|---|
| `../product-brief.md` | Source de vérité produit et messages communs |
| `alternativeto.md` | Fiche AlternativeTo |
| `product-hunt.md` | Brouillon de lancement Product Hunt |
| `saashub.md` | Fiche SaaSHub, avec contrôle de coût préalable |

| `fosshub.md` | Fiche pour l'annuaire de logiciels libres FOSS Hub |
| `awesome-selfhosted.md` | Entrée pour la liste GitHub Awesome Self-Hosted |
| `../assets/` | Instructions pour les captures d'écran (pointeurs LFS) |

## Ordre de priorité

La priorité immédiate est l’optimisation de GitHub, puis AlternativeTo, car ces deux actions peuvent améliorer la découvrabilité sans imposer de paiement de curation. Product Hunt vient ensuite, lorsque l’URL produit, la démo et les captures sont stabilisées. SourceForge est optionnel. SaaSHub est conditionné à l’approbation explicite de la dépense annoncée sur sa page de soumission.

## Garde-fous

Le dépôt indique que le domaine principal est actuellement indisponible et que les déploiements gratuits peuvent être en retard sur `main`. Les fiches utilisent donc une formulation prudente et demandent une URL canonique stable avant publication. Les mentions de conformité doivent rester des postures documentées, jamais des certifications implicites.

## Validation avant publication

1. Confirmer l’URL publique canonique et la page tarifaire ou la mention open source définitive.
2. Vérifier que la démo, les comptes de test et les parcours clés fonctionnent.
3. Confirmer les plateformes réellement disponibles : web, Android, iOS et self-hosted.
4. Valider les pays et règles de paie effectivement supportés.
5. Exporter les captures au format demandé par chaque plateforme.
6. Faire relire les textes en anglais par le responsable produit.
7. Publier manuellement et conserver les URLs de fiches dans un registre de suivi.
